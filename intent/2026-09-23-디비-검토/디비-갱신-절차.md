# TourAPI 연동 → 디비 갱신 절차

> 대상: `intent/2026-09-20-재수집-스키마-교체/` 의 `collect.mjs`(수집) · `load.mjs`(반영)
> 성격: 실행 순서대로 따라가는 운영 문서. 명령 · 옵션의 자세한 설명은
> [수집 폴더 README](../2026-09-20-재수집-스키마-교체/README.md), 판정 규칙의 근거는
> [재수집·스키마 교체 intent](../2026-09-20-재수집-스키마-교체/intent.md), 구조를 정한 이유는
> [서버 수집 검토](../2026-10-09-서버-수집-검토/검토.md) 에 있습니다.

한국관광공사 TourAPI(KorService2)에서 장소를 받아 앱이 보는 `places` 에 반영하기까지는
**두 단계**이고, 매일 0시에 한 번 이어서 돕니다. **파일을 거치지 않습니다.**

```
① 수집   TourAPI → DB tour.*                         collect.mjs
② 반영   tour.* → places · regions · region_groups   load.mjs   (바뀐 장소만)
③ 확인   화면 · 쿼리 · 실행 기록(tour.runs) · 연동 로그(tour.run_logs)
```

②는 TourAPI 를 부르지 않으므로 몇 번을 돌려도 결과가 같습니다 — 판정 규칙을 고쳤을 때
API 를 다시 부르지 않고 `node load.mjs` 만 다시 돌리면 됩니다.

## 0. 사전 준비 (처음 한 번)

### 0-1. API 키

공공데이터포털에서 **한국관광공사_국문 관광정보 서비스_GW** 를 활용신청하면 키가 나옵니다.
수집 폴더의 `.key` 에 한 줄로 넣습니다(gitignore). 서버에서는 환경 변수 `TOUR_API_KEY`.

### 0-2. DB 접속

수집 작업은 `tour_collector` 역할로 접속합니다(마이그레이션이 로그인 없이 만든다).

1. 마이그레이션 적용: 저장소 루트에서 `npx supabase db push --linked` — 앱이 부르는 DB 함수가
   바뀌는 마이그레이션이면 앱 배포(`git push`)보다 먼저 하고, [점검.sql](../2026-10-08-운영-반영/점검.sql) ⑪ 로 확인
2. 비밀번호 정하기 — 수집 폴더에서:
   ```bash
   NEWPW=$(openssl rand -hex 24)
   sed -i '' -E "s#(//tour_collector\.[^:]+:)[^@]*@#\1${NEWPW}@#" .db-url   # .db-url 이 이미 있을 때
   printf "alter role tour_collector with login password '%s';" "$NEWPW" | pbcopy
   unset NEWPW
   ```
   그다음 SQL 편집기에 붙여 넣어 실행(`Success` 확인)하고 클립보드를 덮어 둡니다.
3. 접속 주소: 대시보드 **Connect → Session pooler** 의 URI 에서 사용자 이름을
   `tour_collector.<프로젝트 ref>` 로, 비밀번호 자리를 위 값으로 바꿔 `.db-url` 에 한 줄로(gitignore).
   서버에서는 환경 변수 `TOUR_DB_URL`. (선택) 대시보드의 CA 인증서를 `.db-ca.crt` 로.
4. `npm install`(저장소 루트 — `pg`).

### 0-3. 매일 자동 실행

```bash
cp com.danyoh.oneday-trip.collect.plist ~/Library/LaunchAgents/
launchctl unload ~/Library/LaunchAgents/com.danyoh.oneday-trip.collect.plist 2>/dev/null
launchctl load ~/Library/LaunchAgents/com.danyoh.oneday-trip.collect.plist
```

매일 00:00 `run-daily.sh` 가 수집 → 반영을 돕니다. 맥북이 잠들어 있었다면 깨어날 때 돕니다.

## 1. 수집 — TourAPI → `tour.*`

```bash
./run-daily.sh              # 수집 → 반영 한 번 (자동 실행과 같다)
node collect.mjs            # 수집만
node collect.mjs --sync-dry # 목록 갱신 · 사라진 장소 미리보기 (DB 를 바꾸지 않음)
./run-daily.sh --status     # 진행률 · 최근 실행
```

순서: **목록 갱신**(타입별 전국 목록을 수정일 순으로, 마지막 확인 이후 바뀐 장소만) →
**사라진 장소**(동기화 목록에서 표출 중단을 골라 `hidden_at`) → **목록**(아직 안 받은 시군구 ×
타입만) → **상세**(새 장소 · 수정일이 바뀐 장소만, 장소당 2호출).

- **한도:** 하루 약 2,000호출(상세 1,000곳)에서 멈춥니다(종료코드 1). 정상이고, 다음 실행이
  그 자리에서 이어받습니다. 받은 것은 한 곳마다 바로 저장돼 있습니다.
- **받는 순서:** 콘텐츠 타입 묶음 1(39 · 12 · 14) → 2(28 · 38 · 32) → 3(15 · 25), 묶음마다 목록 → 상세.

## 2. 어느 응답이 어느 테이블로 가는가

수집은 다섯 오퍼레이션을 부르고, 원본은 `tour.*` 에 그대로 쌓입니다. 반영이 그 원본으로
**세 테이블**을 채웁니다. 나머지(`profiles` · `trips` · `trip_items` · `shared_plans` ·
`shared_plan_items` · `plan_ratings`)에는 **API 응답이 한 줄도 들어가지 않습니다.**

```
areaCode2 (파라미터 없음) ──→ tour.code_tables ──→ region_groups   시/도
areaCode2 (areaCode=N) ─────→ tour.code_tables ──→ regions         시군구
areaBasedList2 ─────────────→ tour.list_items ──┐
detailCommon2 + detailIntro2 → tour.details ────┼─→ places          장소
areaBasedSyncList2 ─────────→ list_items.hidden_at ┘  (숨김)
```

### 2-1. `region_groups` ← `areaCode2`

| 응답 필드 | 컬럼 | 비고 |
|---|---|---|
| `code` | `tour_area_code` | PK |
| `name` | `name` | 축약 규칙 적용 — `경기도`→`경기`, `강원특별자치도`→`강원` |
| — | `lat`, `lng` | **API 가 주지 않는다.** 그 시/도 장소들의 좌표 평균으로 계산 |
| — | `sort_order` | 고정 순서(서울 · 경기 · 인천 · 부산 · 제주…) |

### 2-2. `regions` ← `areaCode2` + `areaBasedList2`

| 응답 필드 | 컬럼 | 비고 |
|---|---|---|
| `code` | `tour_sigungu_code` | 부모 `tour_area_code` 와 묶어 복합 PK |
| `name` | `name` | 접두어 없이 `성동구`. 개편 반영 이름은 `load.mjs` 의 `LEAF_NAME` |
| `lDongRegnCd` + `lDongSignguCd` | `ldong_cd` | **장소 응답에서 가져온다.** 그 시군구 장소들이 보낸 값의 최빈값 |
| — | `lat`, `lng` | 그 시군구 장소들의 좌표 평균 |
| — | `sort_order` | 가나다순 |

장소가 0곳인 시군구는 넣지 않습니다(폐지된 행정구역).

### 2-3. `places` ← 목록 + 상세

**목록(`areaBasedList2`)에서 오는 것**

| 응답 필드 | 컬럼 | 비고 |
|---|---|---|
| `contentid` | `id` | PK. 같은 장소를 알아보는 열쇠 |
| `title` | `name` | |
| `contenttypeid` | `content_type` | 원래 타입 번호 그대로 |
| `contenttypeid` · `cat3` · `lclsSystm2` | `category` | 39 → 밥집 · 카페(`cat3` A05020900) · 술집(`lclsSystm2` FD04), 12 · 14 · 28 · 38 · 32 → 명소. 15 · 25 는 넣지 않음 |
| `areacode` | `tour_area_code` | |
| `sigungucode` | `tour_sigungu_code` | 판정을 거친다(응답 코드 → 주소의 시군구 이름 → 미판정 `-1`) |
| `addr1` | `address` | |
| **`mapy`** | `lat` | |
| **`mapx`** | `lng` | `mapx` 가 경도다 — 뒤집으면 지도가 통째로 어긋난다 |
| `firstimage` → `firstimage2` | `image_url` | 앞엣것이 없으면 뒤엣것 |
| `modifiedtime` | `source_modified_at` | 상세를 다시 받을지 정하는 근거 |

**상세(`detailCommon2`)에서 오는 것**

| 응답 필드 | 컬럼 | 비고 |
|---|---|---|
| `overview` | `summary` | HTML 태그를 벗기고 **첫 문장만** |
| `tel` | `phone` | 아래 안내전화 칸이 비었을 때만 |

**상세(`detailIntro2`)에서 오는 것** — 콘텐츠 타입마다 필드 이름이 다릅니다.

| 타입 | `open_hours` | `phone` |
|---|---|---|
| 39 음식점 | `opentimefood` | `infocenterfood` |
| 12 관광지 | `usetime` | `infocenter` |
| 14 문화시설 | `usetimeculture` | `infocenterculture` |
| 28 레포츠 | `usetimeleports` | `infocenterleports` |
| 38 쇼핑 | `opentime` | `infocentershopping` |
| 32 숙박 | `checkintime` · `checkouttime` → "체크인 … / 체크아웃 …" | `infocenterlodging` |

**`tags`** — 응답에서 확실히 나오는 다섯만: 카페(분류) · 주차가능(주차 칸) · 심야영업(음식점
영업시간이 자정 이후 마감 · 24시간 · 익일) · 오마카세 · 디저트(메뉴 글자). 규칙은 `load.mjs` 의 `tagsOf()`.

**API 가 주지 않아 우리가 정하는 값**

| 컬럼 | 값 | 이유 |
|---|---|---|
| `region_source` | 판정 경로 | `tour`/`addr`/`manual`/`unresolved` |
| `region_note` | 미판정 사유 | 관리자가 다시 조사하지 않고 판단하도록 |
| `hidden_at` | 표출 중단 시각 | `areaBasedSyncList2` 의 `showflag 0`. 다시 표출되면 null |

평점 · 가격대는 TourAPI 가 주지 않아 칸이 없습니다. 화면의 ★ 는 사용자 리뷰 평균입니다.

### 2-4. 응답이 들어가지 않는 테이블과 지켜야 할 선

사용자 데이터(`trip_items.place_id` · `shared_plan_items.place_id`)가 `places` 를
`on delete cascade` 로 참조하므로, **장소를 지우면 사용자 데이터가 함께 지워집니다.** 그래서
반영은 장소를 지우지 않습니다 — TourAPI 에서 내려간 장소는 `hidden_at` 으로 숨기고, 수집 역할
(`tour_collector`)에는 지우는 권한 자체가 없습니다.

## 3. 반영 — `tour.*` → `places`

```bash
node load.mjs --dry     # 무엇이 바뀔지만 (DB 를 바꾸지 않음)
node load.mjs           # 반영 (자동 실행은 수집 바로 뒤에 이걸 돈다)
node load.mjs --demo    # 데모 모드 데이터 src/lib/seed.ts 도 다시 만든다
```

- 변환 결과의 지문(`tour.place_out`)과 비교해 **바뀐 장소만** 한 트랜잭션으로 upsert 합니다.
  지역 · 시/도는 매번 통째로.
- 덮지 않는 것: 관리자 등록 장소(`m-`) · 사람이 고친 지역(`region_source = 'manual'`) · 별점 칸.
- 반영할 장소가 지금 `places` 의 90% 보다 적으면 반영하지 않고 실패로 남깁니다(`--force` 로 무시).

## 4. 확인

### 4-1. 화면

**비로그인 상태로 지도 탭**을 여는 게 가장 빠릅니다. 지역 드롭다운에 시/도가 뜨고 구를 고르면
장소가 나오면 공개 읽기까지 제대로입니다.

- 소개 · 영업시간이 빈 장소에 빈 칸이나 빈 제목이 남으면 안 됩니다
- 드롭다운에 '미판정' 이 보이면 안 됩니다

### 4-2. 실행 기록 · 연동 로그

```bash
./run-daily.sh --status       # 진행률 · 최근 실행
node collect.mjs --log        # 마지막 실행의 화면 출력 (--log 12 는 12번 실행)
```

SQL 편집기에서는 [점검.sql](../2026-10-08-운영-반영/점검.sql) ⑥~⑩(권한 · 정책 · 현황 · 최근 실행 · 오류 줄).

### 4-3. 쿼리

```sql
-- 판정 경로별 분포. unresolved 가 급증했다면 수집 · 판정에 문제가 생긴 것이다
select region_source, count(*) from public.places group by 1 order by 2 desc;

-- 수동 처리 대기열
select id, name, address, region_note
  from public.places
 where tour_sigungu_code < 0
 order by name;

-- 상세가 아직 안 채워진 비율
select count(*) filter (where summary = '') * 100.0 / count(*) as 소개_빈_비율
  from public.places;
```

### 4-4. 미판정 처리

대기열의 장소는 주소와 좌표가 그대로 남아 있으므로, 올바른 코드 쌍을 넣으면 그 자리에서
서비스에 등장합니다.

```sql
update public.places
   set tour_area_code = 1, tour_sigungu_code = 5
 where id = '<contentid>';
```

`region_source` 는 건드리지 않아도 됩니다 — 트리거가 자동으로 `'manual'` 로 바꾸고
`region_note` 를 비웁니다. `'manual'` 인 행은 **다음 반영이 지역을 덮어쓰지 않습니다.**

## 5. 자주 걸리는 곳

| 증상 | 원인과 조치 |
|---|---|
| `ERR_NAME_NOT_RESOLVED` (브라우저) · `project is paused` | Supabase 프로젝트가 **Paused**. 대시보드에서 Restore |
| `Cannot find project ref` | `npx supabase link --project-ref <ref>` 를 먼저 |
| `SERVICE_KEY_IS_NOT_REGISTERED_ERROR` | `.key` 를 반대쪽(Encoding ↔ Decoding) 키로. 발급 직후면 잠시 기다린다 |
| 수집이 매번 같은 곳에서 멈춤 | 일일 한도. 정상 — 다음 실행이 이어받는다 |
| `DB 접속 주소가 없습니다` | 수집 폴더에 `.db-url` 이 없다(또는 `TOUR_DB_URL`) |
| `Cannot find package 'pg'` | 저장소 루트에서 `npm install` |
| `password authentication failed for user "postgres"` | `.db-url` 의 사용자 이름이 `postgres.<ref>` 그대로 — `tour_collector.<ref>` 로 |
| `password authentication failed for user "tour_collector"` | 비밀번호가 다르거나, 바꾼 직후 pooler 가 옛 비밀번호를 기억하는 중. 더 바꾸지 말고 30분쯤 기다린다 |
| `Tenant or user not found` | 사용자 이름에 `.<ref>` 가 빠졌다 |
| `EHOSTUNREACH` · `ENOTFOUND` | Direct connection 주소(`db.<ref>.supabase.co`, IPv6 전용)를 넣었다 — Session pooler 주소로 |
| `permission denied for …` (반영) | 마이그레이션이 운영에 다 안 들어갔다 — `db push --linked` 뒤 점검 ⑥ |
| 반영이 '90% 보다 적음' 으로 멈춤 | 수집 · 판정이 크게 어긋났다. 연동 로그를 보고, 의도한 것이면 `--force` |
| `No matching Supabase CLI binary package found for darwin-arm64` | 다른 OS 에서 `npm install` 이 돌았다. `rm -rf node_modules && npm install` |
